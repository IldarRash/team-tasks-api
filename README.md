# Team Tasks API

Kotlin / Spring Boot / Gradle API for team tasks with continuous priorities. PostgreSQL persistence via Spring JDBC, without JPA.

## Run locally

Install Docker Desktop with Linux containers (or Docker Engine + Compose on Linux). Start Docker, then run from this directory:

```sh
docker compose -p team-tasks-api up --build -d
```

The first build downloads JDK images, Gradle and dependencies and needs internet. API: `http://localhost:8080`. Wait until `GET /actuator/health` returns `{"status":"UP"}`. PostgreSQL port 55432 and API port 8080 must be free. Both ports bind to localhost. Inspect startup:

```sh
docker compose -p team-tasks-api ps
docker compose -p team-tasks-api logs --tail=100 api
docker compose -p team-tasks-api restart api
docker compose -p team-tasks-api down
```

Data survives restart and `down`/`up` through volume `team-tasks-api_postgres-data`. **Adding `-v` to `down` erases data.** Credentials are for this local exercise; there is no authentication or public deployment configuration.

## API examples

Replace TASK_ID with the UUID from POST. These examples use a POSIX shell; PowerShell alternatives follow.

```sh
curl -i -X POST http://localhost:8080/tasks -H 'Content-Type: application/json' -d '{"teamId":1,"name":"First task","description":"Implement endpoint"}'
curl http://localhost:8080/tasks
curl 'http://localhost:8080/tasks?teamId=1'
curl http://localhost:8080/tasks/TASK_ID
curl -X PATCH http://localhost:8080/tasks/TASK_ID -H 'Content-Type: application/json' -d '{"name":"Updated task"}'
curl -X PATCH http://localhost:8080/tasks/TASK_ID/priority -H 'Content-Type: application/json' -d '{"priority":1}'
curl -i -X DELETE http://localhost:8080/tasks/TASK_ID
```

PowerShell:

```powershell
$task = Invoke-RestMethod -Method Post -Uri http://localhost:8080/tasks -ContentType 'application/json' -Body (@{teamId=1;name='First task';description='Implement endpoint'} | ConvertTo-Json)
Invoke-RestMethod -Uri 'http://localhost:8080/tasks?teamId=1'
Invoke-RestMethod -Method Patch -Uri "http://localhost:8080/tasks/$($task.id)" -ContentType 'application/json' -Body '{"description":"Updated description"}'
Invoke-RestMethod -Method Patch -Uri "http://localhost:8080/tasks/$($task.id)/priority" -ContentType 'application/json' -Body '{"priority":1}'
Invoke-RestMethod -Method Delete -Uri "http://localhost:8080/tasks/$($task.id)"
```

Contract: [OpenAPI](docs/api.yaml). Priority is generated by the server; supplying it on creation is invalid. PATCH changes only name and/or description. Missing PATCH fields are preserved; null, unknown fields and empty patches are rejected. teamId is a positive 64-bit integer; name is nonblank, up to 200 characters; description is nonblank, up to 10000.

Moving a task shifts neighbours: `[A:1,B:2,C:3,D:4]`, move D to 2 -> `[A:1,D:2,B:3,C:4]`; delete B -> `[A:1,D:2,C:3]`. Priority must be 1..N within that team. A move to the current position succeeds; repeated DELETE returns 404. Lists are ordered by teamId and priority, or by priority with a team filter. No pagination.

POST returns 201 + Location; reads and PATCH 200; DELETE 204. Invalid inputs return 400, missing tasks 404, temporary rollback conflicts after bounded retry 503. Errors have status, code, message, fieldErrors. POST has no idempotency key: retry after an unknown network/commit outcome may create a second task.

## Build and tests

Docker startup requires no host JDK. For development install JDK 17, set JAVA_HOME to that installation and use the checked-in Gradle wrapper (8.13). Spring Boot 3.5.7 and Kotlin 2.1.20 are pinned. No global Gradle is needed.

```sh
./gradlew test bootJar
docker compose -p team-tasks-api up -d db
RUN_POSTGRES_INTEGRATION=true ./gradlew test --rerun-tasks
./gradlew bootRun
```

PowerShell:

```powershell
.\gradlew.bat test bootJar
docker compose -p team-tasks-api up -d db
$env:RUN_POSTGRES_INTEGRATION='true'
.\gradlew.bat test --rerun-tasks
Remove-Item Env:RUN_POSTGRES_INTEGRATION
.\gradlew.bat bootRun
```

Do not run bootRun while Docker API occupies 8080; stop it first with `docker compose -p team-tasks-api stop api`. Datasource defaults to localhost:55432/taskdb with user/password tasks. Override DATABASE_URL, DATABASE_USER, DATABASE_PASSWORD, PORT as needed. DB tests use TEST_DATABASE_URL, TEST_DATABASE_USER, TEST_DATABASE_PASSWORD. They create random teams and remove only their own data. Without RUN_POSTGRES_INTEGRATION=true, DB tests are explicitly skipped; unit-only success does not prove DB behaviour. `--rerun-tasks` avoids reusing a unit-only result after changing the environment.

Tests cover input boundaries, priority shifts, compaction, bounded rollback retries, unknown commit failures, two independent service instances and concurrent readers. Report: `build/reports/tests/test/index.html`.

## HTTP, restart and load checks

Requires running Docker API and Python 3.10+ (standard library only). From this directory:

```sh
python scripts/verify_api.py
python scripts/restart_test.py
python scripts/restart_test.py --recreate --output output/persistence.json
python scripts/load_test.py --users 20 --warmup 30 --seconds 60
```

Use python3 if that is your executable name. Scripts default to 127.0.0.1 to avoid IPv6 localhost connection fallback delays on Windows; override with --base if needed. They create random teams and clean their tasks. Empty team lock rows remain by design. Output JSON files are under output/.

HTTP checks cover CRUD, move directions/no-op, deletion positions, validation, 40 concurrent creations and 120 mixed writes/reads. Restart checks every saved field after restarting only this Compose project's API. Load runs one hot team and ten teams; each workflow performs POST, move to 1, list, DELETE. Default: 20 users, 30 seconds warmup and 60 seconds measurement per scenario. Latency is for the whole four-request workflow, not one request. Pass criterion: zero unexpected errors and continuous final priorities. Performance is measured, with no invented SLA.

To check volume persistence, save a task UUID, run `docker compose -p team-tasks-api down`, start again without `-v`, wait for health UP and GET that UUID. All fields must match.

## Design

Controller parses input; service owns invariants and transaction boundaries; repository uses parameterized SQL. Each write takes a durable team row lock with SELECT FOR UPDATE and re-reads task state after the lock. A deferred UNIQUE(team_id, priority) permits atomic range shifts and checks uniqueness at commit. Lists use one consistent SQL snapshot. Locks work across API instances; different teams are independent.

Retries are limited to three attempts for PostgreSQL rollback SQLSTATEs 40P01/40001. Unknown connection/commit outcomes are not retried. DB constraints enforce uniqueness/positivity; the service ensures continuity. Manual SQL bypassing the service is outside the API guarantee. Reordering is O(N); no unlimited-scale claim is made.

## Delivery

```sh
python scripts/package.py
```

Creates output/team-tasks-api.zip from tracked Git files. Commit changes before packaging. Excludes .git, secrets, build caches and database data. Local Git history is available; add your remote yourself. Nothing is pushed automatically.
